Soutenance · 8 semaines

career-match

Apparier un profil candidat à des offres tech, avec un score explicable : six axes, trois paniers, écarts, simulation de formation.

Le LLM n’invente pas le 0–100.

1 · Introduction

Pas une barre de recherche d’offres

  • Les job boards partent d’un mot-clé : « Dev React Paris ».
  • Quand il y a un score, on ne sait pas pourquoi (compétence, séniorité, sémantique…).
  • Ici, on part du profil : CV, mini-CV, ou exemple Jane Doe.

1 · Introduction

Contrainte structurante

Aucun modèle ne calcule le score.

  • Probabiliste : extraction CV, embeddings.
  • Déterministe : normalisation, filtres, paniers, simulation.
  • Démonstrateur : LLM, RAG, LangGraph, MCP, agent, n8n.

2 · Problématique

Question

Comment apparier un profil à 120 offres de façon explicable, sans laisser un LLM inventer un score, en 8 × 14 h ?

2 · Périmètre

Chaîne de valeur et corpus

Produit

  • Extract → normalize → retrieve → score
  • 6 dimensions, 3 paniers, gaps
  • Catalogue fermé + simulation

Données

  • 120 offres Multi-ATS, CC BY 4.0
  • 20 / famille, max 2 / entreprise
  • 154 compétences, min. 3 occurrences
  • Anglais, tech, pas d’OCR

3 · Architecture

Domain pur

  • domain/ n’importe ni LangChain, ni Postgres, ni le réseau.
  • Un test d’architecture (AST) le vérifie.
  • Conséquence : scoring testable sans mock.
  • Deux couches : RawProfile (LLM) → Profile (normalisé, seul scoré).

4 · Chaîne

Extract · normalize · retrieve

PDF / texte→ LLM JSON→ cascade 0.88→ filtres→ cosine pgvector
  • Groq GPT-OSS 20B + cache disque (hash + prompt + modèle).
  • Normalisation : exact, alias, fuzzy — pas de LLM.
  • RAG = filtres (famille, remote, lieu) puis similarité. Pas BM25.

4 · Chaîne

Score, paniers, simulation

Six axes (somme 1)

mandatory 0,40 · preferred 0,15 · seniority 0,15

semantic 0,15 · education 0,10 · languages 0,05

Le cosine entre comme un float. Le domain n’appelle pas pgvector.

Paniers ≠ total /100

eligible : 0 mandatory manquante

reachable : jusqu’à 3 gaps, séniorité ≥ −2

out_of_reach : séniorité ≤ −3 ou trop de gaps

Cours = clone du profil, re-score. Catalogue fermé.

5 · Rôles de l’IA

Deux modèles, un agent

Modèles

LLM : extraire le RawProfile (et le référentiel, hors ligne).

Embeddings : vecteurs pour le cosine.

Ni l’un ni l’autre ne choisit le panier.

Agent chat

POST /api/chat : outils sur la session déjà scorée.

Cartes, profil, simulate_course.

Il explique. Il n’invente pas un 0–100.

5 · Rôles de l’IA

MCP et orchestrateurs

  • MCP : 5 outils stdio, mêmes corps que le pipeline. Le client découvre les outils (process séparé).
  • LangGraph : enchaîne les nœuds. Un branchement PDF / JSON. Ne calcule pas le score.
  • n8n : appelle POST /api/match, compte les paniers. Zéro inférence.

Le LLM structure · l’embedder rapproche · l’agent explique · le domain décide.

6 · Application

API : façade, pas un second scorer

  • POST /api/match : PDF ou texte ou exemple Jane Doe.
  • Cookie cm_session : cartes en RAM, pas de rescoring aux GET.
  • PUT /api/profile corrige sans graphe ; POST /api/rematch à part.
  • OpenAPI = contrat (/docs).

6 · Application

Essayer puis sauver

  • Le match est ouvert sans compte.
  • Le compte (email + mot de passe, pbkdf2) ne fait que persister le Profile.
  • À la connexion, la session en RAM gagne ; sinon rehydratation JSON.
  • Front Next.js : accueil → 3 paniers → fiche (6 barres, gaps, simulation) → profil → chat.

7 · Évaluation

12 cas or, pas un score cible

  • Jane backend · Maya frontend · Leo data × offres du corpus.
  • Un panier attendu par paire. Runner = score_offer (pas de LLM, pas de Postgres).
  • Les filtres de retrieval sont hors scope : on juge la politique de paniers.

12 / 12 après la seconde passe

7 · Évaluation

Seconde passe (scoring.json)

  • Sidecar d’offre : souvent 5 compétences mandatory.
  • max_mandatory_gaps_reachable : 2 → 3.
  • Poids semantic 0,20 → 0,15 · mandatory 0,35 → 0,40.
  • Exemple : Jane + backend aws/k8s (manque azure, java, go) : mur → reachable.

On n’a pas réécrit score.py. Le défaut Python semaine 3 reste pour les tests unitaires.

8 · Démonstration

Cinq scènes (~8–10 min)

  1. Invité, Jane Doe → trois paniers.
  2. Fiche reachable / out_of_reach : axes, gaps, simulation.
  3. Profil : Save sans rescoring, puis Recalculer.
  4. Compte : le match n’était pas un paywall.
  5. Chat : « why » / « which course » — chiffres issus des outils.

Toujours localhost:3000. Filet chat : Swagger tools_used.

10 · Conclusion

Ce qu’on a montré

  • Une chaîne complète, jalon pivot dès la CLI semaine 3.
  • Les semaines 4–8 n’ont pas réécrit le score : elles l’exposent, l’évaluent, le racontent.

Le modèle structure. Le domain décide.
